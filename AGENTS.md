# ghidra-native component guide

This independent repository owns the native decompiler, Sleigh compiler and processor specifications used by r2ghidra. Paths and commands below are relative to this root. See [the bridge guide](../AGENTS.md) for plugin integration and the separate build-managed engine copy; editing this checkout does not update that copy or its pin. Follow native Ghidra C++/specification conventions in the affected files, not the host's C conventions. The native Meson project currently selects C++14.

For commits, follow [the shared prospective attribution rule](../../AGENTS.md#shared-prospective-commit-attribution).

## Canonical changes and generated followers

- `patches/*.patch` is the canonical local patch stack. `scripts/apply_patches.py` applies these top-level files in sorted filename order and records their byte identity and the prepared source identity in `patch.done` only after completing the stack; Make and Meson use this same runner. `patches/Attic/` is not in that applied set.
- `src/decompiler/` and `src/Processors/` contain imported baselines. Maintain local decompiler, processor-specification and patch-supplied test deltas in the patch stack; do not also commit applied copies of those deltas. Keep algorithm and RE knowledge in code/specifications and focused tests, not instruction prose.
- `patches/0190-target-type-sizes-and-pointer-printing.patch` owns target-size getters, the narrow `PrintC` pointer hook and x86/16 scalar-size/ten-byte `long double` stride metadata. The bridge's `../src/R2TypeDeclaration.cpp` and `../src/R2PrintC.cpp` consume these native boundaries; declaration parsing and target-Sdb-backed layout remain at the host utility owners identified in the workspace map.
- `patches/0220-unsized-array-roundtrip.patch` owns zero-element array codec roundtrips and unsized declaration output. `patches/0230-derived-type-factory-completion.patch` exposes the existing native typedef-completion helper to derived factories; the bridge consumes it through `../src/R2TypeFactory.cpp`.
- `patches/0240-function-prototype-specificity-printing.patch` owns actual-function prototype-specificity printing and its native regression controls.
- `patches/0250-union-pointer-facing-arithmetic.patch` owns union-facing pointer-arithmetic rewrite handling and its native regression controls.
- `patches/0260-anonymous-code-type-interning.patch` owns canonical interning of decoded anonymous callback types and its native regression controls.
- `patches/0270-open-input-hidden-return.patch` preserves existing return-derived hidden parameters through local-symbol cleanup and open-input recovery. A locked aggregate return does not lock the source parameter list; the bridge supplies the native model's existing hidden parameter pieces.
- `patches/0280-qualified-native-types.patch` owns concrete const/volatile type variants, their identity/completion/codec rules and qualified C rendering. `patches/0290-qualified-volatile-accesses.patch` preserves indirect volatile accesses and memory dependencies through existing native operation, heritage, guard, merge and early action owners, retaining CALLOTHER encoding. Its qualifier traversal handles the admitted unambiguous single-member union.
- `patches/0300-explicit-native-type-identity.patch` exposes direct name/ID/display construction, explicit per-enum byte widths, named function-record types and the existing canonical name hash for bridge consumers. Omitted enum width retains the factory default. `patches/0310-callback-model-declarations.patch` owns the narrow named-type expansion hook and callback-model presentation; real aliases and default printer behavior remain separate from bridge function-record bindings.
- `patches/0320-callf-memory-segment.patch` routes the 16-bit operand/address indirect FAR call through the existing `Mem16` address owner. BP addressing uses SS by default, other addressing retains DS, and explicit segment overrides remain effective; target reconstruction and return-frame operations remain unchanged.
- `patches/0330-function-convention-presence.patch` carries supplied convention knowledge separately from the effective model and model locks through native function-type construction, identity, copying and XML/packed codecs. Its callback-only `PrintC::emitTypeModel` hook preserves explicit default conventions without changing actual-function display policy; the bridge supplies its shared declaration carrier through that hook. The existing native parser propagates its retained model spelling through the grammar source and generated follower.
- `patches/0340-protected-mode-wide-addresses.patch` isolates `x86-16-protected.slaspec`/`.pspec` and C48 RAM addressing from the existing Real Mode/SMM inputs. It owns protected-mode instruction address/control propagation, actual FAR-pointer loads and machine-width return frames. `patches/0350-segmented-coordinate-consumers.patch` separates raw near/far pointer widths from analysis coordinates in native types, conversions and symbol reconstruction. `patches/0360-wide-address-regressions.patch` supplies `src/unittests/testsegmentedwide.cc` with real translated-instruction execution and direct type/constant controls. Ordinary near2/far4 pointers and formal stack2 remain distinct from RAM6.
- `patches/0370-relocated-field-values.patch` owns construction-time decoded-field association and the optional machine-field `LoadImage` query. Numeric decoding stays separate from unknown machine-value source cells; static targets are not constructed through this query. It supplies `src/unittests/testrelocatedfields.cc`; [tests/README.md](tests/README.md) describes these construction controls, not qualification of the bridge provider or full selector-value correction.
- `patches/0380-static-segment-references.patch` owns the optional initial-reference and call-preserved-storage queries at `LoadImage`, the cohesive `SegmentOp` implementation in `src/decompiler/segmentop.cc`, its SSA relationship query and direct rule/resolver/printer consumers. `Heritage::guardCalls` consumes independently supplied storage preservation only for otherwise unknown call effects. The patch also owns symbolic Protected16 CS and normal-return FAR-call summaries. `src/unittests/testsegmentreferences.cc` and the scoped TASM controls in `testsegmented.cc` cover these local boundaries; bridge providers remain separate consumers. Numeric selector bits remain distinct from static identities.
- `patches/0390-mixed-width-stack-effects.patch` owns mixed-width call-effect projection in `src/decompiler/ruleaction.cc`, symbolic stack-root/equation handling in `src/decompiler/coreaction.cc` and input possible-nonzero-bit facts in `src/decompiler/funcdata_varnode.cc`. Its focused controls extend `src/unittests/testsegmented.cc` and `testsegmentedwide.cc`; [tests/README.md](tests/README.md) describes their decoded-CFG, mask, cleanup-accounting and uncertainty coverage.
- `patches/0400-call-relative-stack-inputs.patch` owns call-relative input recovery/materialization in `src/decompiler/fspec.cc` and its native-internal declaration in `fspec.hh`, invoked by the existing placeholder-disposal boundary in `heritage.cc`. [tests/README.md](tests/README.md) describes the bounded aligned-stack production comparison and remaining qualification limits.
- A matching `patch.done` validates reuse without Git. Stale, malformed or old empty markers, changed source inputs, and markerless dirty or partly prepared trees refuse without changing source bytes. Preserve changes and prepare a new checkout or use a matching prepared distribution; do not remove the marker and retry on the same tree. Recognized outputs are flat `src/decompiler/*.o` files paired with adjacent `.cc` inputs, processor `.sla` files paired with `.slaspec` inputs, and the imported test target's `src/decompiler/test_dbg/*.o` files paired with `.cc` inputs in `src/decompiler/` or `src/unittests/`, `test_dbg/depend`, its numeric PID temporary and `src/decompiler/decomp_test_dbg`. This does not ignore other files in `test_dbg/` or other imported targets. Canonical sources, headers, grammars, specifications and includes remain checked, including regenerated parser `.cc`/`.hh` bytes.
- `sources.mk` owns the shared native source sets; `scripts/sources.py` exposes them to Meson and embedded consumers. Check native `meson.build` and the bridge's `../src/Makefile`, `../ghidra/deps.mk` and `../r2plugin/` followers when changing source membership or embedding interfaces.
- `src/Processors/<processor>/data/languages/` owns language specifications. The bridge's `../ghidra/` build compiles and installs their runtime followers; changes must be tested with matching compiled languages, not an unrelated installed set.

## Build and focused tests

- `Makefile`, `meson.build` and `meson_options.txt` own the build. `make` or `meson setup <build-dir>` followed by `meson compile -C <build-dir>` prepares fresh sources and builds the native libraries/Sleigh compiler. Make always invokes the runner; Meson configuration and build reuse validate preparation, including exported native dependencies and embedded sources. Fresh preparation mutates the source tree through patch application; inspect the checkout first and use fresh disposable copies for stack validation.
- `make test` enables and runs the Meson regression suite. For a fresh explicit build, use `meson setup <build-dir> -Dtests=true`, `meson compile -C <build-dir>` and `meson test -C <build-dir> --print-errorlogs`. The registered tests cover native regressions and patch preparation, including real Sleigh compilation. See [tests/README.md](tests/README.md) for procedures; `tests/meson.build` and `tests/main.cc` own suite membership, language fixtures and the driver.
- The alternate `make -C src/decompiler test` uses the imported Makefile and requires the GNU toolchain and BFD development files. Run the shared preparation runner before it and validate preparation afterward; that imported target does not call the runner itself. Use matching compiled languages through `SLEIGHHOME`. Parser regeneration that changes canonical input bytes remains an explicit refusal, not an output exemption. The test guide owns this bounded procedure; it does not establish support for every optional imported target.
- Some test sources exist only after applying patches: `patches/0110-win16-segmented-addresses.patch` supplies `src/unittests/testsegmented.cc`, consumed by `tests/meson.build`. Inspect its canonical patch rather than treating a missing unpatched follower as a missing test. `patches/0120-borland-fmovmem-prototype.patch` owns the corresponding local x86 convention specification.
- For documentation-only changes, check references and `git diff --check` without applying patches or rebuilding. Inspect this repository's Git diff/status directly; the parent ignore hides this checkout from parent tracking and searches.

## Destructive maintenance boundaries

`make mrproper` runs `git reset --hard` and `git clean -xdf`; sync targets replace imported `src/decompiler/` or `src/Processors/` trees. These are destructive maintenance operations, not ordinary build/test cleanup. Do not use them to validate a working checkout with edits or retained build evidence.
